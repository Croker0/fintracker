# План тестирования FinTracker

**Версия:** 1.0  
**Ответственный:** Ибрагимов (аналитик)  
**Дата прогона:** 13.11.2026

## 1. Область

Проверяются: учёт операций, категории и теги, фильтры, агрегации и графики, экспорт,
настройки, напоминания, устойчивость к пустым данным и повороту экрана.
Не проверяются: сетевые сценарии (их нет), банковские интеграции, мультивалютность.

## 3. Автотесты

Команда:

```bash
gradlew.bat testDebugUnitTest
```

Покрытие — 15 unit-тестов, все зелёные:

| Набор | Что проверяет | Кол-во |
|---|---|---|
| `MoneyTest` | формат рублей/копеек, парсинг `1 250,50`, отказ от `0` и `-10`, round-trip | 5 |
| `SummaryBuilderTest` | итоги, сортировка категорий, проценты, 13 дневных точек, 12 месяцев, пустые данные, диапазоны периода | 6 |
| `TransactionListBuilderTest` | группировка по датам, заголовки и итоги, поиск по заметке/тегу, фильтры, пустой результат | 4 |

Сборка: `gradlew.bat assembleDebug` — **успешно**, APK 7.1 МБ.
CI: `.github/workflows/android.yml` собирает APK и запускает тесты на каждый push/PR.

### Ручной чек-лист (план прогона)

Статус `⬜` означает, что сценарий нужно пройти на устройстве/эмуляторе перед защитой.
Логика, лежащая в основе сценариев, покрыта unit-тестами и успешной сборкой.

| ID | Проверка | Прогон |
|---|---|---|
| M-01 | Первый запуск: демо-данные появляются, главная не пустая | ⬜ |
| M-02 | Добавление расхода: сумма, категория, дата, тег → строка и баланс обновились | ⬜ |
| M-03 | Валидация: пустая/нулевая/отрицательная сумма, нет категории | ⬜ |
| M-04 | Редактирование суммы и заметки | ⬜ |
| M-05 | Удаление операции, пересчёт итогов | ⬜ |
| M-06 | Переключение периода на главной и в аналитике | ⬜ |
| M-07 | Поиск по заметке, тегу и категории | ⬜ |
| M-08 | Комбинация фильтров «Расходы + категория + поиск» | ⬜ |
| M-09 | Добавление/редактирование категории, цвет и эмодзи | ⬜ |
| M-10 | Запрет удаления категории с операциями | ⬜ |

| M-14 | Тёмная тема: главная, операции, аналитика, настройки | ⬜ |
| M-15 | Поворот экрана: выбранный таб и данные сохраняются | ⬜ |
| M-16 | Очистка операций: пустые состояния, нет крашей | ⬜ |

> На машине сборки эмулятор не использовался из-за аппаратных ограничений.
> Финальный визуальный прогон выполняется на устройстве перед защитой.

## 4. Граничные случаи

| Кейс | Ожидание |
|---|---|
| Нет операций за выбранный период | графики и легенда показывают пустое состояние |
| Очень длинная заметка | обрезается в строке, полностью видна в редакторе |
| 6 тегов и попытка добавить 7-й | сохраняются первые 6 |
| Сумма 999 999 999,99 | принимается; больше — отклоняется |
| Будущая дата | недоступна в date picker |
| Удаление всех операций | категории и настройки сохраняются |
| Смена типа категории с операциями | запрещена с понятным сообщением |
| Повторное имя категории | ошибка «Категория с таким названием уже есть» |
| Нет разрешения на уведомления | напоминание не показывается, приложение работает |

## 5. Нефункциональные проверки

- **Производительность:** список 1 000 операций — плавный скролл, фильтрация < 100 мс.
- **Память:** утечек нет; адаптеры отвязываются в `onDestroyView`.
- **Доступность:** `contentDescription` у иконок, контраст, размер touch-зон.
- **Приватность:** в манифесте нет `INTERNET`; данные только в локальной БД.

## 6. Известные ограничения

1. Нет инструментальных UI-тестов (Espresso) — ручной чек-лист + unit-тесты.
2. «Синхронизация» — локальный JSON-снимок, сервера нет по условиям проекта.
3. Миграции Room не реализованы: версия 1, при изменении схемы — новая миграция.
4. Скриншоты в README — дизайн-макеты, а не снимки с устройства.

## 7. Критерии выхода

- Все unit-тесты зелёные.
- `assembleDebug` без ошибок.
- Пройдены M-01…M-16.
- Нет крашей в сценариях из раздела 4.
