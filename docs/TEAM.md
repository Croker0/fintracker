## 2. Кто чем занимается

### Штефан — главный разработчик, тимлид

**Основные функции.** Собирает приложение целиком: каркас, навигацию, пять вкладок, редактор операции, графики и тёмную тему. Отвечает за архитектуру MVVM, код-ревью, интеграцию веток и релизную сборку.

**Как работает.** Разбивает задачу на «экран» и «данные», сначала согласует контракт с Кисловым, потом верстает экран по макету Давлетханова и подключает ViewModel/StateFlow. Проверяет пустые состояния, поворот и тёмную тему, принимает pull request и следит, чтобы `main` собирался.

**Результат.** Рабочее приложение с пятью вкладками и отдельным редактором, APK и релиз v1.0.0.

### Кислов — backend и база данных

**Основные функции.** Проектирует локальную базу: четыре таблицы, внешние ключи, индексы. Пишет Entity, DAO и репозиторий, отвечает за SQL-агрегации, WorkManager, напоминания, JSON-бэкап и CSV-экспорт.

**Как работает.** Сначала схема и связи, потом DAO-запросы и репозиторий с Flow. Агрегации проверяет unit-тестами, фоновые задачи делает через `CoroutineWorker`, экспорт отдаёт через FileProvider. Стыкует контракты с Штефаном, чтобы экраны получали уже готовые данные.

**Результат.** Локальная `fintracker.db`, работа без интернета, напоминания, бэкап, экспорт и CI-сборка.

### Ибрагимов — аналитик

**Основные функции.** Переводит задание в требования и user stories, фиксирует must-have и could-have, пишет критерии приёмки, метрики и тест-план.

**Как работает.** Разбирает сценарии пользователя, согласует приоритеты с командой, ведёт [REQUIREMENTS.md](REQUIREMENTS.md) и [TEST_PLAN.md](TEST_PLAN.md). Проверяет сборку по чек-листу, заводит баги с шагами воспроизведения и принимает фичу после исправления.

**Результат.** Понятный объём проекта, 16 ручных сценариев и критерии, по которым фича считается готовой.

### Давлетханов — дизайнер

**Основные функции.** Отвечает за визуальный стиль: палитру, типографику, отступы, иконки, тексты и тёмную тему. Делает макеты пяти вкладок и редактора.

**Как работает.** Собирает референсы, задаёт дизайн-токены и рисует макеты в реальных пропорциях экрана. Передаёт Штефану размеры и состояния (обычное, нажатое, пустое), проверяет контраст и одинаковость отступов в готовой вёрстке.

**Результат.** [DESIGN.md](DESIGN.md), четыре макета в `docs/images/`, единый стиль светлой и тёмной темы.

## 4. Процесс работы

- **Доска:** GitHub Projects, колонки `Backlog → In progress → Review → Done`.
- **Ветки:** `main` защищена; задачи — в `feature/<краткое-имя>`, багфиксы — `fix/<...>`.
- **Коммиты:** короткие, в императиве: `feat: add period filter`, `fix: keep tag order`.
- **Pull request:** минимум 1 ревью (обычно Штефан), зелёный CI, описание изменений и скриншот UI.
- **Синхронизация:** 15 минут в начале недели + асинхронные апдейты в чате.
- **Definition of Done:**
  1. код собирается (`assembleDebug`);
  2. unit-тесты зелёные;
  3. нет новых предупреждений lint уровня error;
  4. сценарий проверен вручную;
  5. обновлена документация/строка в README при необходимости.

## 7. Риски и mitigation

| Риск | Вероятность | Влияние | Меры |
|---|---|---|---|
| Расхождение макета и реализации | средняя | среднее | макеты по реальным размерам, ревью UI |
| Сложность агрегаций по датам | средняя | высокое | SQL-группировка + unit-тесты `SummaryBuilder` |
| Нехватка времени на полировку | высокая | среднее | must-have фичи в первую очередь, could-have — в конце |
| Разные часовые пояса у команды | низкая | низкое | хранение epoch millis, локальная зона только для отображения |
| Потеря данных при смене схемы | низкая | высокое | экспорт схемы Room, версия БД, TODO на миграции |

## 8. Демо-сценарий защиты (5 минут)

1. Первый запуск: демо-данные, главный экран, переключение периодов.
2. Добавление расхода: сумма, категория, дата, тег → возврат на главную.
3. Поиск и фильтры в «Операциях», удаление операции.
4. Аналитика: топ категорий, инсайт, график.
5. Настройки: время напоминания, экспорт CSV, тёмная тема.
6. Архитектура на слайде: Room → Repository → ViewModel → UI, WorkManager, CI.
